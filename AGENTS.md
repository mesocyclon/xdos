# xgos

Проект Go-библиотеки для DOCX и собственного PDF по architecture.md.
Сейчас есть только архитектура; реализация и её проверка ещё не выполнены.

## Границы работы

- Авторитетный архитектурный документ — architecture.md; инструкции пользователя имеют приоритет.
- Autopilot: manual deep. Спецификация и план требуют явного согласования до разработки.
- Общий источник истины XML/OPC; изменения не создают второй изменяемой модели.
- Расход памяти и вычислений обосновывается данными и операцией; локальная правка не скрывает полный обход. Проверять масштабирование публичным API.
- Пакеты отражают ответственности, данные и инварианты; объединение/разделение обосновывается связностью. Направленные зависимости проверяются автоматически.
- Исправлять общую причину у владельца правила, прослеживая потребителей; не дублировать логику и не вводить частные обходы. Несвязанный код не менять.
- Runtime библиотеки: pure Go, без cgo и внешних конвертеров/браузеров.
- Комментарии в коде по-русски, одна строка, до 10 слов; назначение каждой новой или изменённой функции комментируется.
- Использовать существующее окружение; новые Docker-окружения для проверки не создавать. Volumes не удалять, prune не выполнять.
- Не выдавать структурную проверку документа за runtime, fidelity или benchmark библиотеки.

## Как здесь работает Autopilot

Требования, спецификация и таски — в .autopilot/. Состояние — .autopilot/state.js,
дашборд — .autopilot/dashboard.html. Требования снимает только пользователь.
Прерванный прогон продолжает команда «продолжи автопилот».

## Правка без автопилота

Сначала прочитать .autopilot/PROGRESS.md, если существует, и относящиеся к изменению ADR.
Историю читать прицельно: git log --oneline -10 -- <файл>, git log -S <текст> -- <файл>.
После правки записать факт в PROGRESS.md, не переопределяя договорённости пользователя.
Коммит — с конкретными путями; чужие изменения не включать.
Заголовок «Autopilot: сборка сдана» используется только после приёмки прогона.
